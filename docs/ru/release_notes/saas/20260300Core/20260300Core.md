### **Новый раздел для навигации по бизнес-процессам**

Новый раздел **Рабочие ситуации и запросы** — единая точка входа, когда нужно создать заявку. Задача раздела — уменьшить количество ошибок и обращений в HR: сотрудники видят, что можно оформить в системе, и находят нужное действие быстрее.  
Категории охватывают основные рабочие ситуации: отпуска, рабочее время и выходные, командировки, справки, персональные данные и документы, выплаты и льготы, переводы и изменение условий труда.

### **Главная страница для аккаунта**

Добавили все виджеты в аккаунты. Это дает всем клиентам с несколькими юрлицами возможность настроить единую главную страницу для всех сотрудников одновременно.

Доступные виджеты:

* **Быстрые действия** — создание популярных заявок в один клик.  
* **Активные запросы** — все текущие заявки собраны в одном месте.  
* **Сервисы руководителя** — быстрый доступ к разделам для работы с командой.  
* **Сервисы сотрудника** — ссылки на личный кабинет, справки, отпуска и другие разделы для личных задач.  
* **Календарь** — ближайшие события и даты прямо на главной.  
* **Электронные сервисы** — переходы во внешние сервисы, которые используются в работе.  
* **Мои ссылки** — каждый сотрудник настраивает под себя: добавляет нужные ссылки вручную.  
* **Ближайшие отпуска** *(новый)* — видно, кто из коллег и руководителей уходит в отпуск в ближайшее время.  
* **Дни рождения коллег** *(новый)* — чтобы не пропустить поздравление.

По умолчанию сейчас сотрудники по-прежнему видят главную страницу своей компании. Чтобы переключить их на главную аккаунта, перейдите в **Настройки виджетов компании** → кнопка **Сбросить до аккаунта**.  
После добавления виджеты расставлены в произвольном порядке — администратору надо проверить расположение и настройки.

<warn>

Для управления настройками главной страницы аккаунта нужна роль **Администратор главной страницы** (роль должна быть создана в аккаунте и назначена пользователю, даже если у него есть аналогичная роль в рамках компаний)

### **Фильтры в листингах**

В блок быстрых фильтров добавлен **новый фильтр «От меня»** — пользователь увидит все заявки, которые создал сам. Актуально при массовых рассылках и для ролей, которые создают много заявок: теперь не нужно разбирать общий список, где перемешаны свои и чужие.  

В списках заявок, сотрудников и корпоративных документов **в фильтре «По подразделению» появилась опция «включая дочерние»**. При её включении в выборку включается не только выбранное подразделение, но и все вложенные в него отделы. Удобно для компаний с многоуровневой структурой: не нужно выбирать каждый отдел вручную, чтобы увидеть полный список по подразделению. Поведение фильтров по умолчанию в разделах не изменилось.

### **Автоматизация рассылки табелей руководителям**

Для всех компаний, где руководители должны согласовать табель учета рабочего времени своих подчиненных, — теперь можно настроить рассылку заявок из 1С документа. По кнопке «Отправить в КЭДО» для каждого подразделения будет создана заявка с табелями сотрудников этого подразделения. В заявке можно настроить цепочку согласований руководителей аналогично тому, как работает расчет в заявках сотрудников.

При старте из 1С-документа «Табель» система автоматически разбивает его по подразделениям и создаёт отдельную заявку на каждое. Распил можно делать по юридической или управленческой структуре — зависит от настройки на уровне 1С-модуля.

Если руководитель отвечает за несколько подразделений, он получает несколько заявок. Назначенные для этого бизнес-процесса заместители также имеют доступ к действиям в заявках.

Настройка автоматизации рассылки табелей будет доступна после выпуска новой версии расширения 1С 2026.03.00.

### **Произвольное значение в атрибуте-справочнике**

В атрибутах типа «справочник» теперь можно ввести значение вручную, но не сохранять его — оно не добавляется в справочник и не перегружает его лишними данными. Раньше, если был доступен ввод своего значения, оно автоматически сохранялось в справочник и становилось доступно для выбора будущим пользователям.  




### **Новая опция валидации**

При выборе дат периода в заявке система умеет проверить, что выбранный пользователем период — не больше или не меньше определенного количества дней. Новая опция позволяет явно указать, надо считать праздничные дни в периоде или нет.

## **Организационная структура**


### **Автоматическое назначение заместителей на время отсутствия руководителя**

Для временных заместителей на отсутствия руководителя — система будет автоматически подключать их к заявкам в течение периода отсутствия. Раньше заместителя нужно было вручную привязывать к каждому отсутствию.

Доступ заместителя определяется по календарю руководителя: в течение периода отсутствия руководителя заместитель будет добавляться во все новые заявки, где участвует его руководитель. После окончания периода замещения у заместителя остается доступ только к заявкам, в которых он выполнил действие за руководителя. К остальным заявкам доступ закрывается.

Для компаний без обмена отсутствиями с 1С остаётся возможность указать период вручную.

В ближайших релизах планируем доработать функционал так, чтобы заместитель автоматически добавлялся во все активные заявки, где ожидается участие его руководителя. Ждем!

### **Данные штатного расписания в оргструктуре**

Теперь руководители могут видеть в оргструктуре, сколько ставок в штате занято и свободно — без ручных выгрузок из 1С.

Данные по штатному расписанию добавлены в карточку подразделения — штат, замещённые и вакантные ставки с учётом дочерних и отдельно по подразделению. Удобно для планирования найма и контроля укомплектованности.

В списке сотрудников незакрытые вакансии будут отображаться отдельными карточками — с должностью и количеством свободных ставок. У каждого сотрудника появится бейдж — процент ставки, который он занимает.

Функционал будет доступен полностью после выпуска новой версии расширения 1С 2026.03.00.

* Может быть ситуация, когда не все ставки штатной позиции закрыты, тогда будут отображены данные по сотрудникам и блок вакансии.

Процент занятости при этом рассчитывается в соответствии с графиком работы сотрудника:<br> Проверяется значение "График работы" в карточке сотрудника (справочник "Сотрудники" в 1С):<br> а. | Замещена частично  |1. Условия назначения бейджа: сотрудник нанят на неполную ставку штатной позиции (по сотруднику по этой штатной позиции в 1С заполнены атрибуты: Вид занятости позиции = Занята, Количество ставок < 1).<br> 2. Процент занятости ставки высчитывается в соответствии с количеством ставок, которые занимает пользователь (несколько полных или часть от одной).<br>  Например:<br> &bull; если сотрудник нанят на полставки, то указывается 50%,<br> &bull; если сотрудник нанят на 1/4 ставки, то указывается 25%.<br> При этом на эту штатную позицию на оставшуюся часть ставки можно нанять ещё сотрудника. - В оргструктуре не выводится информация по сотрудникам, которые совмещают несколько штатных позиций (т.е. у штатной позиции атрибут "Вид занятости" = "Совмещена").   
- Если в документе 1С "Совмещение" указан "Вид совмещения" = "Исполнение обязанностей сотрудника", то:   
    - В веб-сервисе будет выведена штатная позиция и в ней указан сотрудник, который занял её первично.  
    - Информации о совмещении не будет, в том числе не будет добавлено, кто на эту позицию назначен совместителем.  
    - При расчёте показателей подразделения: общее количество позиций штатного расписания и количество вакансий не изменится, количество занятых будет увеличено согласно количеству занимаемых ставок, с учётом совмещения.  
- Если в документе 1С "Совмещение" указан "Вид совмещения" = "Совмещение должностей (профессий)", то:   
    - Вакантная позиция не выводится в веб-сервисе, если на позицию нанят сотрудник, то отображается информация о нём.   
    - При расчёте показателей подразделения: общее количество позиций штатного расписания не изменится, количество занятых будет увеличено согласно количеству занимаемых ставок, а количество вакансий уменьшено соотвественно.   
- При этом для этих штатных позиции не будет указано, что они совмещены и кто на них назначен.

**Вакантные позиции**: 

* Если атрибут 1С штатной позиции "СтавокСвободно" больше 0, то в этом случае отображается карточка "Вакансии".  
* Для каждой вакансии указывается: название должности и информация о количестве доступных вакансий.  
* Количество доступных вакансий может быть нецелым числом.   
* Информация о количестве доступных вакансий система получает из 1С.

## **Отпуска и отсутствия**

### **Передача дней отгула за работу в выходные и праздничные дни из 1С в КЭДО**

Добавлена передача дней отгула за работу в выходные и праздничные дни из 1С в КЭДО. Возможности:

* информация по накопленным дням для отгулов будет импортироваться в КЭДО из 1С и храниться в системе как один из лимитов отпусков;  
* сотрудник сможет просмотреть данные по доступным дням в разделе **Мой календарь** → виджет **Дни отпуска** → кнопка **Просмотреть детализацию** → тип отпуска **Другой день отдыха за работу в выходные и праздничные дни**.  
* сотрудник сможет создать заявку с видом отпуска «Другой день отдыха за работу в выходные и праздничные дни».

Бизнес-ценность:

* поддержка бизнес-процесса по предоставлению дней отгула за работу в праздничные и выходные дни (заявка, валидация);  
* информирование сотрудника о доступных днях с помощью виджета.

Функциональность будет доступна после выпуска новой версии расширения 1С 2026.03.00.

## **График отпусков**

### **Планирование графика отпусков по подразделениям**

Добавили возможность создавать планирование графика отпусков по подразделениям в рамках одного юридического лица. Ранее можно было создать только по всему юридическому лицу в целом. Возможность доступна для пользователей с ролью «Менеджер графика отпусков».

Новые планирования запускаются также через **Сервисы компании** → **Настройка → Графики отпусков**.

В каждом планировании можно настроить тип оргструктуры и выбрать подразделения, указать дату окончания планирования для сотрудников подразделения.

Далее сотрудники заполняют планирования, а руководители и кадровые специалиста их согласовывают — в рамках каждого созданного планирования отдельно.

Бизнес-ценность:

* поддержка в решении бизнес-процесса крупных компаний;  
* возможность настройки такого планирования для разных подразделений по разным сценариям.

<details>
<summary>Создание нового планирования Менеджером графика отпусков</summary>

1. Перейдите в раздел **Сервисы компании** → **Настройка → Графики отпусков** и нажмите кнопку **Создать новое планирование**.   
2. Выберите тип оргструктуры и добавьте подразделения из выпадающего списка в соответствии с оргструктурой компании. Запрещено добавлять подразделение, для которого уже было создано планирование. 

![](./assets/admin_setting_addVacation-1-4-1.png)

3\. Заполните все обязательные поля и перейдите к следующему шагу создания планирования.  
4\. После успешного создания график отпусков появится в общем списке планирований.
   
![](./assets/admin_setting_Vacation-5-1.png)

5\. Чтобы просмотреть детали планирования, нажмите на график отпусков с подразделениями.

![](./assets/admin_setting_Vacation-5-2.png)

</details>

### **Согласование графика отпусков функциональными руководителями**

На текущий момент в КЭДО согласование осуществляется административными руководителями по оргструктуре. Новая настройка позволит направлять на согласование заявку как административному, так и функциональному руководителю.

При настройке маршрута согласования на этапе запуска планирования графика отпусков можно добавить дополнительно функционального руководителя в качестве согласующего. Возможности:

* будет добавлена новая роль функционального руководителя;  
* при настройке планирования будет добавлен выбор типа руководителя: при выборе функционального — согласование происходит функциональным руководителем и руководителем по юридической оргстурктре;  
* функциональному руководителю доступны такие функции при согласовании, как иным руководителям по оргструктуре.

Если функциональный руководитель не найден, то этот этап пропускается и осуществляется переход к следующему согласующему.

Если при назначении один сотрудник является руководителем по разным типам (например, и как юридический, и как функциональный) — на согласование назначается только одна задача.

Бизнес-ценность:

* Возможность согласования отпуска сотрудника всеми руководителями, в процессах которых сотрудник выполняет задачи.

Выбор типа согласующего руководителя добавлен в интерфейс настройки планирования графика отпусков.

#### **Поиск по сообществам и постам сообществ**  

Появился единый поиск по сообществам и их контенту. Можно находить **сообщества**, **посты внутри сообществ** и **комментарии к постам** по ключевым словам. Поиск помогает быстро перейти к нужной теме, обсуждению или ответу, даже если вы не помните, где именно это было опубликовано.

Преимущества:
* Быстрее находите нужное: один запрос — и результаты сразу по сообществам, постам и комментариям.  
* Экономия времени: меньше ручного просмотра ленты и веток обсуждений.  
* Проще ориентироваться в большом количестве сообществ: легко найти релевантное сообщество по теме и сразу увидеть активные обсуждения.  
* Повышает повторное использование контента: старые полезные посты и ответы легче найти и не создавать дубликаты вопросов.  
* Ускоряет коммуникацию: быстрее находите, кто и где уже обсуждал вопрос, и можете продолжить диалог в нужной ветке.  
* Улучшает качество обсуждений: меньше повторяющихся тем, больше ссылок на уже найденные ответы и контекст.

Подробнее в статье [Поиск по социальным сервисам](/ru/hr/portal/search). 

#### **Модерация постов**  

В сообществах появилась возможность включить **модерацию постов**. Обычные участники могут предложить пост к публикации, а сотрудники с административными правами в сообществе проверить его и согласовать или отклонить. Это помогает поддерживать качество контента и единые правила публикаций в сообществе. 

Преимущества:
* Контроль качества и соответствия правилам: публикации проходят проверку перед размещением в ленте сообщества.  
* Снижение шума и нерелевантного контента: меньше случайных/дублирующих/неподходящих постов.  
* Безопасность и корректность: проще предотвращать публикацию чувствительной информации, нарушений и некорректных формулировок.  
* Единый стиль и структура: администраторы могут поддерживать форматирование, теги, тональность и стандарты сообщества.  
* Удобный вклад участников: участники по-прежнему могут делиться идеями и материалами, не теряя возможности быть услышанными.  
* Повышение доверия к сообществу: лента становится более полезной и предсказуемой по качеству, что увеличивает вовлечённость.

### **Опросы**

#### **Аналитика по прохождению опросов** 

Сотрудники с правами администрирования опросов могут смотреть результаты по каждому вопросу как в общем виде, так и в разрезе конкретных сотрудников.  
Обычные сотрудники могут видеть общую статистику по каждому вопросу (кроме текстовых), если администратор включил настройку просмотра ответов опроса сотрудниками. 

Преимущества:
* Быстрое понимание итогов: наглядная общая статистика по каждому вопросу без ручного подсчёта.  
* Глубокий анализ для администраторов: возможность смотреть результаты по конкретным сотрудникам помогает разбирать спорные случаи, уточнять контекст и повышать качество данных.  
* Гибкое управление доступом: администратор сам решает, показывать ли результаты сотрудникам, и тем самым балансирует открытость и конфиденциальность.  
* Защита чувствительных данных: текстовые ответы не отображаются в общей статистике для сотрудников, что снижает риск раскрытия персональных формулировок.  
* Повышение доверия и вовлечённости: когда результаты (в допустимом виде) доступны, участники чаще воспринимают опрос как полезный инструмент, а не формальность.  
* Ускорение принятия решений: аналитика помогает быстрее выявлять тренды и проблемные зоны по конкретным вопросам.

Подробнее в статье [Просмотр аналитики по опросам](/ru/hr/portal/survey/management/analytics).

### **Текстовый редактор**

#### **Мини-опросы в текстовом редакторе**  

В текстовом редакторе новостей и постов появилась возможность добавлять мини-опросы. Мини-опрос — это опрос из одного вопроса, который отображается в конце текста публикации. В одном материале можно добавить несколько мини-опросов.

Поддерживаются следующие типы ответов: 
* Один вариант из нескольких,  
* Несколько вариантов из нескольких,  
* Текстовый ответ.

Для каждого мини-опроса можно настроить, показывать ли результаты всем сотрудникам или скрывать их (при этом по текстовым ответам общая статистика не отображается).

Преимущества:
* Быстрый сбор обратной связи без отдельного опроса: мини-опросы создаются прямо при подготовке новости/поста.  
* Единая точка взаимодействия: все вопросы собраны в конце публикации, читателю удобно ответить после прочтения.  
* Гибкие форматы ответов:   
  * один вариант — для голосований, выбора и т.д,  
  * несколько вариантов — для чек-листов, сбора предпочтений и т.д.,  
  * текст — для комментариев, предложений и т.д.  
* Несколько вопросов в одной публикации: можно собрать мнения по разным аспектам темы, добавив несколько мини-опросов.  
* Управление прозрачностью: автор/администратор решает, показывать результаты всем или оставить их только для анализа.  
* Конфиденциальность текстовых ответов: отсутствие общей статистики по текстовым ответам снижает риск раскрытия персональных формулировок.

Подробнее в статьях [Создание новости](/ru/hr/portal/news/management/create) и [Создание поста](/ru/hr/portal/communities/work/create_post).
