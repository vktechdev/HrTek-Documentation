## **Бизнес-процессы**

### **Добавление участников в заявку из документа 1С**

Если в документе 1С указан конкретный подписант, система теперь может автоматически назначить его исполнителем нужной роли в заявке КЭДО. Маппинг между полями в 1С документе и ролями в бизнес-процессе КЭДО можно настроить на процесс один раз, и дальше участники будут подставляться автоматически, в том числе и в рамках уже активной заявки. Такое автозаполнение участников заявки возможно при загрузке документа из 1С в уже запущенную заявку или при создании заявки из 1С. Для роли в бизнес-процессе должна быть включена опция «Выбор согласующего».  

Для работы функционала Администратор настраивает маппинг в разделе 1С: **КЭДО → Начальная настройка → Соответствие документов → Соответствие реквизитов**. Необходимо связать поле документа с ролью в  бизнес-процессе. Для роли в бизнес-процессе должна быть включена опция «Выбор согласующего». Роли с такой опцией станут доступны для маппинга автоматически.  

Автоматическое заполнение исполнителя из 1С доступно только при одновременном выполнении условий:  
1. В заявке происходит загрузка документа из 1С на старте или в активной заявке.  
2. В бизнес-процессе для роли указана опция «Выбор согласующего».  
3. В бизнес-процессе настроена опция заполнения исполнителя из 1С документа.
4. В 1С настроены оба маппинга (документы и реквизиты).  
5. Реквизит указывает на подходящего пользователя. В реквизите документа 1С указан пользователь, и для него одновременно верно:  
- есть хотя бы один неуволенный сотрудник,  
- этот сотрудник подключен к КЭДО,  
- сотрудник может быть исполнителем этой роли. 

Если исполнитель из документа 1С не передан или не прошёл проверки, заявка продолжает работу по стандартной логике роли.

## **Отпуска и отсутствия**

### **Детализация накопленных дней отпуска в разрезе периодов их накопления**

Доработаны возможности получать из 1С накопленные дни отпуска по периодам их накопления и отображать такую детализацию в виджете **Детализация отпускных дней** в разделе **Мой календарь**.  

Доступные дни отпуска отображаются:
* в разрезе периодов накопления, если такие данные есть;  
* без детализации по периодам, если данных по периодам нет.

На странице **Мои сервисы → Мой календарь** → виджет **Дни отпуска →** кнопка **Посмотреть детализацию** → форма **Детализация отпускных дней** для каждого вида отпуска дополнительно будут отображаться периоды накоплений дней:  
   * начало периода накопления дней отпуска;  
   * окончание периода накопления дней отпуска;  
   * количество накопленных дней отпуска в указанном периоде (не суммируются дополнительно с данными без периодов).

Для вида отпуска «Другой день отдыха за работу в выходные и праздничные дни» детализация по периодам не отражается.

### **Валидатор на количество дней компенсации**

В заявке на компенсацию неиспользованных дней отпуска реализована корректная валидация указанного количества дней компенсации на соответствие доступному количеству дней по каждому выбранному виду отпуска (лимита):

* пользователь указывает, какой лимит компенсируется;  
* тип лимита выбирается из списка лимитов, полученных из учетной/кадровой системы;  
* для выбранного типа лимита система отображает доступное количество дней;  
* пользователь указывает, сколько дней по нему компенсируется;  
* система проверяет, что запрашиваемое количество дней не превышает доступный остаток по выбранному виду отпуска;  
* в заявке будет поддерживаться нескольких строк — несколько видов лимитов компенсации.

## **Уведомления**

### **Кнопки действий для email-уведомлений**

В email-уведомления для руководителей и их заместителей добавлены кнопки «Согласовать» и «Отклонить». При нажатии на кнопку пользователь переходит в личный кабинет VK HR Tek, где:  
- «Согласовать» — согласование выполняется **автоматически** при переходе, заявка переводится на следующий этап. Если этап уже был завершён (например, если этап был пройден автоматически по дедлайну или ранее был согласован заместителем) — состояние заявки не меняется.  
- «Отклонить» — открывается форма отмены заявки с выбором причины и комментарием. 

Если пройти по ссылке «Перейти к заявке» — открывается заявка для ручных действий.  

В рамках текущей реализации согласование **не происходит прямо в письме** — пользователь всё равно переходит в веб-интерфейс VK HR Tek, где действие выполняется автоматически.   

**Условия отображения кнопок:**  
- Текущий этап имеет тип действия «согласовать».  
- Уведомление отправлено по одиночной заявке (не агрегированное).  
- Получатель — руководитель по любой оргструктуре или его заместитель.

### **Уведомление «Подтвердите выпуск УНЭП на Госуслугах»**

SMS-уведомление «Подтвердите выпуск УНЭП на Госуслугах» стало дефолтным. Теперь данное уведомление автоматически включено для всех компаний.

**Как это работает:**  

- Если пользователь выпускает УНЭП через Госуслуги, но сразу **не подтвердил** личность на Госуслугах — система напомнит ему об этом.  
- Уведомление содержит инструкцию перейти на Госуслуги ([https://lk.gosuslugi.ru](https://lk.gosuslugi.ru)) и завершить подтверждение.  
- Проверка запускается каждый час и ищет сотрудников, подавших заявление в последние 24 часа (но не раньше 4 часов назад).  
- Уведомление отправляется **не чаще одного раза в сутки** на одного сотрудника.

**Бизнес-ценность:**   

Напоминание позволяет избежать ошибки «Удостоверение личности через ЕСИА: время ожидания истекло», после которой процесс выпуска УНЭП нужно проходить заново.

## **МЧД**

### **Запрет на подписание документов с истекшей МЧД**

Добавлена настройка, которая проверяет валидность машиночитаемой доверенности (МЧД). Если срок действия МЧД истёк — подписание документа невозможно.   

**Что видит пользователь:**  

При попытке подписать документ с истекшей МЧД — ошибка: «Срок действия МЧД истек. Загрузите обновленную МЧД».  

Если МЧД отсутствует у пользователя, то проверки и ошибки не будет.

- Дата окончания МЧД \< текущей даты → ошибка, документ не подписан.  
- Для всех существующих аккаунтов настройка подключается автоматически.  

**Бизнес-ценность:**  

Защита от юридических рисков: документы, подписанные с истекшей МЧД, не имеют юридической силы. Автоматическая проверка предотвращает такие ситуации на этапе подписания.

### **Корректировка поиска с учетом новой ролевой модели**

Добавили отдельный блок в настройках ролевой модели для управления расширенным набором полей, отображаемых в результатах поиска сотрудников (контактные данные, отсутствия и др.). Поиск выполняется по расширенному набору атрибутов, добавлена фильтрация по дням рождения. Также реализована настройка на уровне компании/аккаунта, которая включает/выключает доступность поиска по сотрудникам.  

**Бизнес-ценность:**  

1. Расширение ролевых настроек поиска сотрудников повышает скорость и точность поиска нужных людей: пользователи видят в результатах только разрешённые данные (контакты, отсутствия и т.д.), могут искать по большему числу атрибутов и быстро находить сотрудников по дням рождения.  
2. Дополнительно появилась настройка на уровне компании/аккаунта, позволяющая централизованно включать или отключать поиск по сотрудникам — это усиливает контроль доступа и соответствие требованиям безопасности.

### **Добавление объектов в «Избранное»**

Реализован новый раздел бокового меню — **Избранное**. Пользователь может добавлять и убирать из избранного новости и посты. Видимость раздела зависит от того, включены ли на аккаунте/компании сервисы **Новости** и/или **Сообщества**. 

В разделе также доступен блок рекомендаций: подборки формируются по топ-3 категориям объектов, которые пользователь добавлял в избранное. Если данных недостаточно — показываются популярные публикации за последние 30 дней. Из рекомендаций исключаются уже просмотренные и уже добавленные в избранное объекты.  

**Бизнес-ценность:**  

1. Раздел **Избранное** позволяет пользователям быстро возвращаться к важным новостям и постам, снижая время на повторный поиск и повышая вовлечённость в корпоративный контент.
2. Дополнительно блок рекомендаций помогает открывать релевантные публикации (по интересам пользователя или по популярности), увеличивая охват и просмотры.
3. Гибкая видимость по включённым сервисам (Новости/Сообщества) и правам доступа обеспечивает корректное соблюдение настроек компании и безопасности.
